# 验收说明

## 一、检查前准备

1. 确认 MySQL80 服务正在运行。
2. 按 `README.md` 初始化 `financial_analysis` 数据库。
3. 启动 `backend/target/financial-analysis.war`。
4. 浏览器优先打开现代 Web 管理端 <http://localhost:8006/web/>，使用 `root / 123456` 登录。原 JSP 管理端仍保留在 <http://localhost:8006/admin/pc/login>，用于兼容和功能对照。

首次启动会自动装载 2021 年样例数据，约需要几秒到几十秒。如果数据库已经存在报表数据，只补充缺失的报表类型，不会覆盖已有公司资料。

## 三、Excel 导入验证

样例文件位于原始资料目录：

`2021年链接版KIS旗舰版格式/2021年链接版KIS旗舰版格式/`

1. 利润表页面导入 `损益表202112.xlsx`。
2. 资产负债表页面导入 `资产负债表202112.xlsx`。
3. 现金流量表页面导入 `现金流量表202112.xlsx`。
4. 科目余额表页面导入 `科目余额表202112.xlsx`。
5. 账龄分析页面导入任一 `应付账款账龄分析2021xx.xlsx` 或 `预付账款账龄分析2021xx.xlsx`。
6. 批量导入页面同时选择多个文件，观察文件识别和成功导入列表。

导入后的验证 SQL：

```sql

SELECT COUNT(*) FROM t_basi_assets_and_liabilities;

SELECT TYPE, COUNT(*) FROM t_age_analysis GROUP BY TYPE;
SELECT COUNT(*) FROM t_report_result;
```

## 四、移动端验收路径

1. HBuilderX 打开 `mobile` 目录。
2. 运行到 Chrome，登录 `root / 123456`。
3. 经营报告：检查健康分、收入、净利润、资产、经营现金和风险提示。

## 六、已处理的原项目问题

- 原项目 `financial` 缺少控制层、服务层、数据访问层和 JSP 所依赖的接口。
- 原页面使用的 Redis 会话、`allBag-springboot`、`basicManager` 依赖不适合直接交付；新项目改为 MySQL + HttpSession + token，减少环境依赖。
- 原项目利润表导入模型是“每个项目一条记录”，但数据库和页面按“每个会计期间一条记录、多列金额”设计；已按真实结构重写。
- `t_age_analysis` 没有 `BATCH_ID` 字段，已避免向不存在的字段插入数据。
- 批量导入结果页的 SQL 已改为安全的多表合并查询，避免派生表字段错误。
- 移动端接口统一返回 `{ code, message, data }`，登录失效返回 401。
